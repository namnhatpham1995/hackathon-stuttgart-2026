# Running the workflow in Claude Code, Cursor and Gemini CLI

Use this file when a skill starts an agent role (`proposal-review`, `full-feature-develop`,
`test-fidelity-review`) or when you work in Cursor or Gemini CLI. The skills and agent definitions
under `.claude/` are the single source of truth for every tool; the other tools reach them through
the files below.

## What each tool loads

| Tool | Project instructions | Skills | OpenSpec commands |
|---|---|---|---|
| Claude Code | `CLAUDE.md` | `.claude/skills/` | `/opsx:propose`, … (`.claude/commands/opsx/`) |
| Cursor | `AGENTS.md` → `CLAUDE.md` and this folder | `.claude/skills/` and `.cursor/skills/` (OpenSpec) | `/opsx-propose`, … (`.cursor/commands/`) |
| Gemini CLI | `GEMINI.md` → `AGENTS.md`, `CLAUDE.md` and this folder | `.gemini/skills/` and `.agents/skills/` | `/opsx:propose`, … (`.gemini/commands/opsx/`) |
| Codex | `AGENTS.md` | `.agents/skills/` | the `openspec-*` skills |

- `.cursor/`, `.gemini/` and the `openspec-*` folders in `.agents/skills/` are generated by
  `openspec init --tools claude,codex,cursor,gemini`. Regenerate them with `openspec update`; never
  edit them by hand.
- `full-feature-develop`, `proposal-review` and `test-fidelity-review` in `.agents/skills/` and
  `.gemini/skills/` are pointers to `.claude/skills/<name>/SKILL.md`. Change the skill there, never
  the pointer.
- Where a skill says `$ARGUMENTS`, Claude Code fills it in; in Cursor and Gemini CLI it is what the
  user wrote after the skill's name ("full-feature-develop add-team-invites").
- `ux-review` runs in Claude Code only: it drives the browser through Claude's browser tools.

## Models

One session plans and implements a task group, on the strongest model of its tool, never a fast or
"auto" tier. The agent roles that judge (proposal review, PR review, test fidelity) run on that tier
too:

- Claude Code: Opus.
- Cursor: the strongest model in the model picker (Claude Opus, or the top GPT or Gemini option),
  with Auto and fast models switched off for the run.
- Gemini CLI: the Pro model (`/model`), not Flash.

Judging stays independent through a fresh context, not a different model: a role never sees the
plan, the conversation or the reasoning of the session whose work it judges.

## Starting an agent role

The roles are defined in `.claude/agents/<role>.md` (`proposal-reviewer`, `independent-pr-reviewer`).
The prompt is the same in every tool:

```text
Act as the agent defined in .claude/agents/<role>.md: read that file now and follow it exactly,
including its limits and its return format. Inputs: <the inputs the calling skill names>.
```

Start it with the first option your tool offers:

1. **A subagent with a fresh context.** Claude Code: the Agent tool with the role's agent type (it
   carries `model: opus`); when this session has no such type, a `general-purpose` agent with
   `model: "opus"` and the prompt above. Cursor: a subagent (Task) with the prompt above; when the
   role is listed by name (Cursor can read `.claude/agents/`), pick it. Gemini CLI: a subagent, when
   your version offers them, with the prompt above.
2. **A headless run of the same tool's CLI**, from the worktree, in the foreground, with tool use
   allowed so the role can run `git`, `gh` and tests. Check the flags with `--help` first: only the
   Claude Code line was verified here.
   - Claude Code: `claude -p "<prompt>" --model opus --permission-mode acceptEdits --allowedTools "Read Grep Glob Bash Edit Write"`
   - Gemini CLI: `gemini -m <pro model> --yolo -p "<prompt>"`
   - Cursor: `cursor-agent -p "<prompt>" --model <strongest model> --force`
3. **Neither available:** stop where the skill would start the role, print the full prompt and ask
   the user to paste it into a new chat on the strongest model. Go on when the role's report file
   exists.

Never take the role yourself in the session that wrote the work it judges. A role is continued in a
later round with `SendMessage` in Claude Code only; elsewhere start a new one with the first round's
inputs plus the earlier report files.
