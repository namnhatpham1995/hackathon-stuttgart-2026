# Design System: TradeReady

## Overview

**Supplier workspace**

TradeReady is a calm supplier workspace for scanning buyer requirements, adding documents, and reading an evidence report. The approved direction combines Vanta and Drata task structure with Atlassian foundations and publicly available Atlaskit components. The Operate surface uses medium density, a left-aligned working list, and progressive disclosure.

Neutral surfaces and hairline dividers carry the structure. Blue identifies actions and selection. Paired semantic colours identify evidence states. New products, drafts, uploads, and reports use the signed-in account’s stored data. Explicit CAP-104 examples and older browser-local drafts remain available. The text assistant uses the authenticated API and the same stored findings.

**Characteristics**

- One working list with aligned columns and expandable detail.
- Compact Inter typography, restrained corners, and no decorative elevation.
- Semantic status includes an icon and a written label in both themes.
- Plain action labels and explicit demo, declared, and read-only states.

## Colors

The normative values above come from `src/app/globals.css` and use paired Atlassian light/dark colours, converted from `@atlaskit/tokens` (20.9.0) to OKLCH. Unsuffixed entries are light. The `-dark` entries apply to the same role in dark mode. Components consume the existing CSS variables, whose values change with the theme.

### Primary

- **Action blue** (`accent`, `accent-ink`, `accent-hover`) identifies primary actions and selected text. Dark mode uses light blue with a dark foreground.
- **Selected blue** (`selected`, `selected-ink`) identifies the current sidebar item, selected product navigation, and SDK selection roles. Focus uses the separate `focus` token and a 2px outline with a 2px offset.

### Neutral

- **Work surface** (`card`) covers the main workspace, inputs, lists, and assistant dialog. **Navigation surface** (`paper`) covers the sidebar, list headings, expanded details, and quiet hover states. Both are neutral, without a decorative colour cast.
- **Primary and supporting text** (`ink`, `muted`) covers body copy and metadata. **Dividers** (`line`) separate content. **Control boundaries** (`control-border`) identify fields.
- **Control feedback** (`neutral`, `neutral-hover`, `neutral-pressed`, `subtle-hover`, `subtle-pressed`) defines SDK neutral and subtle actions. `blanket` dims the page behind the native dialog.

### Semantic states

| Role | Meaning and use |
|---|---|
| `documented` / `documented-ink` | Green fill and text for DOCUMENTED |
| `missing` / `missing-ink` | Orange-amber fill and text for MISSING |
| `mismatch` / `mismatch-ink` | Red fill and text for MISMATCH |
| `expired` / `expired-ink` | Yellow fill and text for EXPIRED |
| `review` / `review-ink` | Blue fill and text for NEEDS_REVIEW |
| `banner` / `banner-ink` / `banner-border` | Amber section message for expired certificates and incomplete processing |
| `danger` | Inline form and operation errors |

SDK success/green, danger/red, warning/yellow, orange, and information/blue text roles map to these foreground variables. SDK success, danger, warning, and information icon roles are also mapped explicitly. Status colour always accompanies its icon and label.

**The Paired State Rule.** Every status keeps its matching fill and foreground in both themes. SDK text and icon roles resolve to the same theme-aware semantic foreground.

**The Evidence Rule.** Use documented/open counts and named findings. Do not turn document coverage into a readiness score or a certification claim.

## Typography

Body and headings use Inter, loaded through `next/font` with swap and a `ui-sans-serif, system-ui, sans-serif` fallback. Monospace uses IBM Plex Mono with a `ui-monospace, monospace` fallback, reserved for part numbers, revisions, and exact evidence quotations. Numbers use tabular figures. App text uses normal letter spacing.

| Role | Observed use |
|---|---|
| Headline | Page title (1.625rem, 600, 1.2), becomes 1.5rem at 479px and below |
| Title | Section heading (1rem, 600, 1.3) |
| Body | Main copy (14px, 400, 1.45) |
| Label / metadata | Metadata (13px, 400, 1.4), with 500 weight for field labels and row names |
| Supporting detail | Requirement IDs, filenames, table headings, and counts (12px) |
| Citation | Exact quotation (13px, 400, 1.7), with a 75ch maximum measure |

SDK body font roles bind to the same Inter stack at 14px/20px for buttons and 12px/16px for compact lozenges.

## Layout

Use the existing 8px foundation with 4px subdivisions. Common gaps are 8–12px, with local half-steps such as 6px inside controls. Page sections use 24–32px spacing. The content is left aligned and fills its working region.

| Region | Desktop | Responsive changes |
|---|---|---|
| Sidebar | Sticky, 208px wide, full viewport height, 64px brand row | At 1100px and below, 184px. At 767px and below, hidden, with brand/account controls in the top bar |
| Top bar | Minimum 64px, padding 12px 40px | Horizontal padding 24px at 1100px, 20px at 767px, 16px at 479px |
| Main | Full width, maximum 1280px including padding, padding 32px 40px 56px | 28px 24px 48px at 1100px, 24px 20px 40px at 767px, 16px horizontal at 479px |
| Evidence row | Minimum 76px, padding 12px 20px, 20px column gap. Columns use `minmax(0, 1.25fr) 132px minmax(0, 1fr) 92px` | At 1100px, title, 116px status, 82px action, filename moves below. At 479px, title on its own line, status/action below, filename on the third line, padding 16px 12px |
| Expanded evidence | Padding 20px 24px 24px 46px, prose and quotes limited to 75ch | At 479px, 16px padding |
| Assistant dialog | Fixed at the right, width `min(400px, 100%)`, height 100dvh | Occupies the available width on narrow screens |

Filenames use proportional type and truncate within the row, with the full filename available as a title. Expanded citation filenames may break anywhere. Product tables become lists below 768px. Creation forms cap at 36rem. Request drafts and profile blocks cap at 48rem.

| Screen | Default composition | Disclosure |
|---|---|---|
| Products | Breadcrumb, page title, New product action, one product table/list, browser-storage note | New product replaces the table with one form step |
| Onboarding | Step number, heading, explanation, visible fields, actions | First product collects the supplier profile, then product draft. A later product reuses a non-demo profile in this browser and starts at the draft, Back opens the profile |
| Product documents | Product metadata, Documents / Evidence report navigation, one requirement list | Row expansion shows the buyer requirement and finding. Product details exposes the declared profile and editable draft, Additional files exposes unmatched PDFs and reference photos |
| Evidence report | Metadata, documented/open totals, Findings / Action plan / Request draft tabs | Findings expand to the requirement, reason, all citations, and next action. Supplier profile opens separately |
| Shared report | Read-only label, report tabs and evidence detail | Document mutation links and product navigation are omitted |
| Assistant | Top-bar trigger | Right-side modal dialog with Close and Escape dismissal, then focus returns to its trigger |

## Elevation & Depth

Neutral tone, 1px borders, and dividers provide depth in the flat workspace. The dialog uses a translucent `blanket` backdrop and a left border. No decorative elevation is applied to workspace cards. A dark-mode shadow token exists in the global stylesheet but is not a rule for these working surfaces.

**The Flat Workspace Rule.** Separate working surfaces with neutral tone and 1px dividers. Do not add decorative card shadows.

## Shapes

Working containers, fields, origin badges, and link buttons have restrained rectangular corners (4–6px). SDK default buttons and compact lozenges use the small radius (4px), cards and fields use the medium radius (6px). Borders are 1px. Use the existing line SVG icons, normally 16px, without decorative circles or tiles.

## Components

### Buttons

Shared `Button` actions use `@atlaskit/button/new` with primary, default (secondary), and subtle (ghost) appearances. The wrapper sets minimum heights of 44px default and 32px compact. The SDK owns loading and disabled states. Stable SDK feature variants are selected through the supported resolver because this app has no Atlassian feature-gate service.

Navigating buttons use the existing Next.js link adapter with 6px corners, 14px horizontal padding and 44px minimum height by default. Compact links use 10px padding, 13px type and a 32px minimum. Primary links use action blue, secondary links use `paper`, and ghost links start transparent. Pending links show “Opening…”. Link buttons and navigation entries shrink to 0.98 when pressed only when motion is allowed, SDK actions use SDK pressed-colour feedback.

### Status lozenges and provenance

`StatusChip` uses `@atlaskit/lozenge`, with its icon, sentence-case status label, paired semantic fill/foreground, small radius (4px), compact height (20px) and maximum label width (200px). These indicate the evidence status. Preserve each SDK semantic foreground in dark mode, including the nested icon and text.

Draft origins use the small neutral bordered labels You, Assistant, and From document. Editing an origin-bearing value changes its visible origin to You, unchanged values retain their recorded origin after save.

### Cards and section messages

Lists and working containers use `card`, 1px `line` borders, and 6px corners. Headers commonly use 20px padding, row/detail padding follows Layout. Amber section messages use a 1px semantic border, an icon, and padding of 8px vertically and 12px horizontally. State the problem and recovery action in text.

### Fields and forms

Fields have a visible 13px label, `card` background, 1px `control-border`, 6px corners, minimum height 44px, and 8px by 12px padding. Textareas start taller. Focus uses the shared outline. Hint/error IDs are associated with the control, and error copy uses `danger` with `aria-invalid` and an alert. Validation focuses the first invalid field, changing onboarding steps focuses the new heading. Pending submission disables the fieldset and shows loading feedback. Entries survive validation errors, Back, and failed requests.

### Navigation and report tabs

The supplied passport symbol is the brand mark on sign-in, sign-up, workspace choice, and application headers. It sits on a fixed light `brand-surface` so the navy cover stays visible in both themes. Authentication shows the symbol above the form heading.

One account can use both workspaces. The default post-sign-in dashboard offers Supplier and Buyer as separate choices, and a shared workspace navigation row provides an explicit switch with selected state. Supplier tools stay under `/workspace`, buyer tools under `/buyer`, and shared Board, Directory, and Inbox pages under `/connections`. The connections shell includes Back to workspaces. In the supplier sidebar these three links form a vertical list, while narrow screens and connections pages use wrapping horizontal navigation. Email sign-in links preserve the selected on-site destination.

The sidebar carries global navigation and account controls, the top bar carries Assistant and the single theme control. The selected sidebar entry has both a tinted background and `aria-current="page"`. Product navigation uses a 2px selected underline and 44px targets. Atlaskit Tabs provides the report's tab/panel relationships, keyboard navigation, selection and focus. Findings, Action plan, and Request draft replace the same working area.

### Upload and report states

Staged files say Ready to assess and expose Undo. Replacement keeps the previous active file until the new batch is assessed. Additional files remains available at capacity and opens when it contains pending files. The visible bounds are five PDFs, two reference photos, and 4 MB per file, invalid files and invalid replacements show a local error while preserving the batch. Photos are reference only. A staged document does not display its predecessor’s evaluated status.

No-report states show an explanation and an Add documents action for an editable workspace. Read-only reports omit that action. Incomplete processing identifies unreadable files and asks for replacement. Action plan lists unresolved findings as numbered steps, Request draft can be copied, with manual-copy recovery if the clipboard fails. It does not send a message. Demo products are labelled explicitly, the current demo correction resolves R3, while R2 remains expired and R4 remains missing.

### Assistant and theme control

The assistant is closed by default. Its native modal dialog has a minimum 64px header, scrollable content region and bottom composer. The panel has a typed composer, conversation history, pending and retry feedback, and an optional speaker control. It accepts messages while an assessment runs. Validated directives close the dialog and open the requested product, upload, report, or replacement view. Speech off skips audio requests and retains the complete reply as text. Speech uses up to the first 600 characters of a reply.

The theme control is a 16px sun/moon SVG in the shared top bar. CSS theme variables set its geometry from the server-rendered theme and system preference. The disc/mask/rays transition over 240ms with `cubic-bezier(0.16, 1, 0.3, 1)`, rays fade over 160ms ease-out. With reduced motion, transitions are removed and the final state renders immediately. Theme choice is persisted in a cookie, no choice follows the system. The accessible name names the destination theme.

## Do's and Don'ts

### Do

- **Do** use the shared Button, Field, NavItem, and StatusChip primitives, with Atlaskit handling SDK control behaviour.
- **Do** preserve visible labels, inline error text, first-invalid focus, pending feedback, and reduced-motion behaviour.
- **Do** keep supplier declarations distinct from evidence and keep field provenance visible while editing.
- **Do** keep the assistant closed until requested and clear about configuration or request failures while preserving typed input.
- **Do** name actions plainly with “Upload and assess”, “Save draft”, and “Copy request”.

### Don't

- **Don’t** add scores, percentages, gauges, progress rings, “verified”, or “Compliant” badges.
- **Don’t** use white text on a saturated status pill or invent a second brand accent.
- **Don’t** add gradients, glass, glows, coloured shadows, decorative illustrations, emoji, or marketing hero headings to the workspace.
- **Don’t** use a display serif, another sans-serif identity, or radii above 8px.
- **Don’t** imply that demo assessments or browser-local products use stored account data, or that the copy-only request draft sends a message.
